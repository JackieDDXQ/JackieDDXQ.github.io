# 出行项目收藏页设计

## 目标

让具备产品或技术背景的读者看见：一次看似简单的扫码充电，如何横跨和包、觉观与特来电；产品工作如何把身份、权益、交易和异常恢复组织成一条可理解、可继续的体验。

## 方向选择

1. 保留现有深色长文：内容完整，但与新版首页及权益项目页割裂，难以从问题进入。
2. 完整复制权益项目的空间文件夹：一致性最高，但会把权益项目的呈现形式误当成所有项目的固定模板。
3. 使用同一收藏系统，建立项目专属的“行程控制台”：保留卡片、阅读路线、材料状态和详情阅读器，以路线、站点、状态和资金轨迹呈现充电项目。采用此方向。

## 信息架构

- 总览：项目范围、角色、阶段和三方边界；强调当前是方案设计与联调前对齐材料。
- 默认路线“跟随一次充电”：三方接力 → 核心旅程 → 状态语义 → 异常恢复 → 用户端原型。
- 路线“理解产品决策”：三条链路 → 自动启充 → 恢复原订单 → 最终账单 → 资金表达。
- 路线“看三方如何协作”：三方接力 → 权威状态 → 事件与查询 → 交付材料。
- 全部材料：13 个内容节点，按结构、决策、实践、思考标注。

## 事实边界

- 内容取自现有 `projects/chuxing-equity.html` 与已存在的用户端、管理端原型。
- 页面只陈述方案中的角色边界、流程、状态、产品规则和交付内容；不声称已经上线或产生业务增长。
- 原型用于解释交互和规则，不作为真实运行证据。
- 个人职位沿用现有页面“产品经理”；具体团队分工、联调结果与上线状态仍需后续材料补充。
