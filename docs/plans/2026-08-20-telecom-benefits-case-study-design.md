# 运营商权益案例页重构设计

## 目标

将现有 `projects/rights-management.html` 从后台功能与成果罗列，重构为一篇解释“复杂业务如何被组织成可运行产品系统”的深度案例。页面首先服务于招聘者快速阅读，同时通过系统图谱和规则实验展示产品建模能力。

## 已确认方案

采用原生增强型独立项目页：保留现有 URL、主站导航与静态部署方式，在单页内部建立局部视觉系统和交互脚本，不增加新的框架或构建依赖。

页面保持与主站一致的暖白纸张、档案编号、衬线标题和棕色强调色，但使用更宽的编辑网格、系统线路、注释标签和深色端到端章节形成探索性。设计关键词为 Editorial、Systematic、Quiet、Precise、Tactile、Credible。

## 信息架构

页面采用四层体验：

1. Story：默认阅读路径，包含项目概览、业务矛盾、系统边界、四项产品决策、完整链路与交付复盘。
2. Atlas：覆盖式系统图谱，可从供给、服务、增长和用户触点探索核心对象及上下游关系；关闭后恢复原阅读位置。
3. Lab：嵌入 Story 的小型规则实验，包括供应商主备切换、库存调度、三级策略判断和领取状态映射。
4. Evidence：使用现有云仓、万象、灵霄及数据看板原型作为证据入口，不将后台截图作为叙事主体。

Story 章节固定为：00 概览、01 业务矛盾、02 系统边界、03 供给标准化、04 权益配置、05 套餐与渠道策略、06 用户领取体验、07 端到端链路、08 产品交付。

## 内容原则

- 围绕产品判断组织内容，不按三个后台逐项介绍功能。
- 明确区分业务事实、产品范围、团队成果和个人贡献。
- 没有材料支持的周期、角色、规模和效率数据不得保留或新增。
- 使用“核心工作”“产品产出”等可验证口径，不把未经确认的团队工作全部写成个人主导。
- 原型链接只承担证据作用，并标明会在新窗口打开。
- 缺失的个人复盘使用克制的公开说明，不渲染空白大数字或虚构占位。

## 交互与降级

- Story 在 HTML 中完整存在，不依赖 JavaScript 加载。
- Atlas、Lab、Evidence 都使用原生按钮、ARIA 状态和键盘操作。
- 页面不接管滚轮，不使用无限动画；端到端链路可播放、暂停或重播。
- `prefers-reduced-motion` 下取消位移和自动播放，直接显示完整信息。
- 移动端将章节目录转为水平滚动，图谱和表格转为纵向条目。
- 所有全局事件在页面卸载时清理；独立样式均限定在 `telecom-case` 命名空间内。

## 验证

- 运行仓库现有 build。
- 检查内部链接和原型入口文件是否存在。
- 在 1440px 与 390px 视口检查首屏、章节导航、Atlas、Lab、Journey 和页尾。
- 验证键盘焦点、Escape 关闭覆盖层、Reduced Motion 与无 JavaScript 的核心可读性。
