项目背景

一、行业背景与业务痛点

随着5G时代的到来，运营商面临着激烈的市场竞争和用户增长瓶颈。为提升用户粘性和ARPU值，运营商需要通过丰富的权益体系来增强产品竞争力。然而，原有的权益运营存在以下核心痛点：

  • 业务碎片化严重：10+省级单位及专业公司各自为政，业务规则不统一，难以形成规模化运营能力
  • 权益品类复杂：涵盖茶饮、音视频、生活服务等数十种权益类型，结算口径复杂，资金风险高
  • 系统对接困难：上下游系统多达数十个，接口标准不统一，新业务接入周期长达数月
  • 数据孤岛问题：各系统数据独立，缺乏统一的业务视图和运营分析能力
  • 履约效率低下：权益发放依赖人工干预，自动化程度低，用户体验差

二、需求分析与战略定位

基于深度的业务访谈和竞品分析，项目团队明确了以下核心需求：

  • 统一运营能力：构建集团级权益运营中台，实现规则统一、流程统一、数据统一
  • 快速接入能力：通过配置化方式，将新单位接入周期从月级缩短至周级
  • 全链路可观测：建立金融级对账机制，确保每一笔资金流向可追溯
  • 高可用架构：支撑千万级用户规模，确保系统稳定性和业务连续性
  • 横向扩展能力：支持B2B2C商城等新业务形态的快速孵化

三、项目目标与价值主张

本项目旨在打造一个具备高可用、强协同、可扩展的千万级用户权益运营平台，为运营商的精细化会员运营和业务快速拓展奠定坚实基础。通过"云仓+万象+灵霄"三层架构设计，分离库存、商品与履约能力，实现业务的高效协同与精细化运营。

系统总体架构与定位

基于"分而治之、协同作战"的设计理念，中台采用三层架构设计，将库存、商品与履约能力分离，实现各系统的独立演进与横向复用：

架构设计理念

  • 职责分离：每个系统聚焦核心职责，避免职责混杂导致的系统耦合
  • 松耦合协同：通过标准化接口和事件驱动机制实现系统间解耦
  • 独立演进：各系统可独立迭代升级，不影响其他系统正常运行
  • 横向复用：核心能力可被多个业务场景复用，提升投资回报率

云仓系统（Depot）- 供应链基础层

作为商品供应链中枢，汇聚并管理来自各大供应商的商品/服务资源池，为万象提供标准化的商品来源。

核心定位：
  • 统一商品数据标准，消除供应商差异
  • 实时库存同步，确保供应稳定性
  • 供应商接口统一管理，降低对接复杂度

万象系统（Omni）- 权益中枢层

作为权益管理与核销中枢，负责将云仓的商品包装成权益，进行权益的创建、配置、库存管理及面向最终用户的发放/核销，是运营商权益业务落地的核心网关。

核心定位：
  • 权益生命周期全流程管理
  • 规则引擎驱动的智能配置
  • 实时核销与数据回传

灵霄系统（Cel）- 渠道推广层

作为渠道推广与套餐办理平台，负责管理各省运营商套餐，对接信息流广告渠道，提供套餐办理接口，并处理从广告曝光到用户办理的整个推广业务流程。

核心定位：
  • 全渠道推广策略管理
  • 标准化套餐办理流程
  • 实时数据统计与分析

系统协作关系图

数据流方向：灵霄系统（推广前端）→ 万象系统（权益中枢）→ 云仓系统（供应链）

触发机制：用户办理 → 运营商确认 → 权益触发 → 库存扣减 → 权益下发 → 核销回传

核心接口：套餐办理接口、权益触发接口、库存查询接口、核销回传接口

核心功能

云仓系统

  • 商品库管理：聚合来自各个供应商的标准化商品
  • 商品与规格关联：商品可关联具体供应商，定义规格
  • 供应的稳定性：负责与供应商的接口对接与库存同步
云仓系统

万象系统

  • 权益库存管理：从云仓同步商品，形成可发放的“权益库存”
  • 权益精细配置：将商品包装成具体权益，定义配置编码、权益类型等参数
  • 核销任务管理：支持创建实时生成任务和历史订单任务
万象系统

灵霄系统

  • 策划管理：管理全部的套餐信息
  • 渠道与推广管理：定义信息流渠道，配置不同渠道可推广的策划套餐
  • 办理流程：提供标准的短信下发、验证码验证、套餐办理接口
  • 限办策略：支持设定办理量、时间等限制
灵霄系统

核心业务流程

一、流程背景与触发条件

该流程的核心目标是实现"用户办理套餐 → 权益自动发放"的端到端闭环。触发条件包括：

  • 运营商营销活动启动，需要向办理特定套餐的用户发放权益
  • 用户通过信息流广告、线下营业厅等渠道办理指定套餐
  • 运营商BOSS系统确认套餐办理成功，并触发权益发放事件

二、完整业务流程详解

01

广告投放与用户触达

前置条件：运营人员在灵霄系统配置推广策划、渠道规则和目标用户画像

执行过程：信息流渠道（今日头条、抖音等）根据灵霄配置的定向规则，向目标用户群体投放联合会员套餐广告。广告创意包含套餐权益描述、价格和办理入口。

关键数据：曝光量、点击率、转化漏斗数据实时回流至灵霄系统

02

用户办理与验证

用户行为：用户点击广告后，进入H5办理页面，填写手机号并提交

系统处理：渠道调用灵霄套餐办理接口，灵霄系统执行以下验证：

  • 用户身份验证（手机号格式、运营商归属）
  • 限办策略校验（是否符合办理条件、办理次数限制）
  • 套餐可用性检查（库存、有效期）

输出：办理成功/失败结果，成功则返回办理订单号

03

运营商确认与权益触发

触发机制：运营商BOSS系统收到办理请求后，完成套餐开通并向万象系统发起"权益触发"回调

万象处理：接收触发请求，解析权益配置，确定发放规则

  • 查找对应的权益配置编码
  • 检查权益库存是否充足
  • 确定发放方式（短信、APP推送等）
04

权益库存扣减与下发

库存交互：万象系统调用云仓接口，执行库存扣减操作

卡券获取：云仓系统从供应商获取具体的权益卡券（如卡号密码、兑换码）

权益下发：万象系统通过短信网关将卡券信息发送至用户手机

数据记录：记录权益发放日志，更新订单状态

05

用户核销与数据回传

用户使用：用户收到短信后，前往对应平台（如腾讯视频APP）进行兑换

核销验证：供应商系统验证卡券有效性并完成核销

数据回传：供应商将核销结果回传给云仓系统，云仓同步至万象

对账结算：系统自动生成结算数据，支持财务对账

三、异常处理机制

针对流程中的各种异常情况，系统设计了完善的容错机制：

  • 办理失败：返回明确错误码，支持渠道重试或用户重新办理
  • 库存不足：触发预警机制，通知运营人员补货
  • 下发失败：自动重试机制，短信失败转其他渠道
  • 核销异常：支持人工介入处理，确保用户权益

四、流程价值与业务影响

该闭环流程实现了：

  • 全自动化：从用户办理到权益下发全程无需人工干预
  • 实时性：权益下发时效从原有的T+1提升至分钟级
  • 可追溯：每一步操作都有完整日志记录，支持问题排查
  • 数据驱动：全链路数据回流，支持运营分析和优化

技术实现与系统间数据流

一、技术架构设计

  • 分布式事务补偿机制：采用最终一致性方案，通过消息队列实现跨系统事务的可靠传递
  • 统一事件中心：基于Kafka构建事件总线，实现系统间解耦和异步通信
  • 高可用架构：采用多活部署、自动故障转移，确保99.99%的系统可用性
  • 弹性伸缩能力：基于Kubernetes实现容器化部署，支持业务峰值的自动扩容
